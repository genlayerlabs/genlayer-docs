# DApp Development Workflow with GenLayer

DApp development with GenLayer is the lifecycle for creating, testing, deploying, and connecting decentralized applications built with Intelligent Contracts. This guide explains how developers can move from using **GenLayer Studio** for their first Intelligent Contract to an advanced local development workflow, then finish by building a frontend application with **GenLayerJS**.

---

## 1. Starting with GenLayer Studio

**GenLayer Studio** is an integrated environment designed to streamline the initial stages of Intelligent Contract development, making it accessible for developers of all experience levels.

It provides an interactive environment that serves as a comprehensive sandbox for developing, deploying, and testing Intelligent Contracts in real time. This environment enables developers to experiment with their contracts and see immediate results without the complexities of a production setup.

The platform runs a simulated network with customizable validators that accurately mirror the GenLayer consensus mechanism. This feature allows developers to test their contracts under conditions that closely resemble the actual blockchain environment, ensuring reliable deployment outcomes.

### Choose a Studio environment

Each Studio environment is a separate chain with its own RPC, chain ID, and consensus deployment. Pick one for the current stage and select it explicitly in every tool you use: the Studio UI, the CLI, and the SDK.

| Environment | Studio UI | RPC | Chain ID | CLI alias | GenLayerJS chain | Use it for |
|:--|:--|:--|:--|:--|:--|:--|
| Localnet | `http://localhost:8080` | `http://localhost:4000/api` | 61127 | `localnet` | `localnet` | Full control, resets, custom validators and providers |
| Studionet | [studio.genlayer.com](https://studio.genlayer.com) | `https://studio.genlayer.com/api` | 61999 | `studionet` | `studionet` | Zero-setup hosted development |
| Studio-dev | [studio-dev.genlayer.com](https://studio-dev.genlayer.com) | `https://studio-dev.genlayer.com/api` | 61997 | `studio-dev` | `studioDevnet` | Validating the next release candidate only |

See [Networks](/developers/networks) for explorers, faucets, and wallet settings.

<Callout type="warning">
Studio v0.123 and later charge protocol fees on deploys and writes. Use GenLayer CLI **v0.40.0 or later**, the first release that sends fee options. Until v0.40.0 is published as `latest` on npm, install the release candidate explicitly with `npm install -g genlayer@rc`. Earlier versions install without errors but cannot deploy to a fee-charging Studio.
</Callout>

### Step 1: Connect to the environment

**Hosted (Studionet or Studio-dev)**

1. Open [studio.genlayer.com](https://studio.genlayer.com), or [studio-dev.genlayer.com](https://studio-dev.genlayer.com) for the release-candidate stack. Nothing needs to be installed.
2. Fund the Studio account with the 💧 faucet button in the account selector.
3. To work with the same environment from a terminal, install the CLI and select the matching alias:

```bash
npm install -g genlayer@rc       # v0.40.0 or later; use genlayer@latest once v0.40.0 is released
genlayer --version
genlayer network set studionet   # or: genlayer network set studio-dev
genlayer network info            # confirm the RPC and chain ID before signing
```

The `studio-dev` alias exists only in the matching release-candidate CLI/SDK. If `genlayer network list` does not show it, upgrade the tooling. Never point the `studionet` alias at the Studio-dev RPC: the chain IDs and consensus deployments differ.

**Local (Localnet)**

1. Install Docker 26+ and the CLI, then start the local stack:

```bash
npm install -g genlayer@rc     # v0.40.0 or later
genlayer init                  # choose LLM providers and the number of validators
genlayer up                    # starts validators, the RPC, and the Studio UI
genlayer network set localnet
genlayer network info
```

2. Open `http://localhost:8080` for the Studio UI. Tests, scripts, and frontends connect to `http://localhost:4000/api`.
3. Run `genlayer up --reset-db` when you need a clean chain. See [Development Setup](/developers/intelligent-contracts/tooling-setup) for all `init` and `up` options.

### Step 2: Prepare an account for CLI and SDK deployments

The Studio UI signs with its own browser accounts, and the 💧 button only funds those. To deploy from the CLI or from scripts, create a local account:

```bash
genlayer account create --name studio-dev-account   # creates an encrypted keystore (--name is required)
genlayer account          # shows the address, balance, and active network
```

The account needs GEN for the fee deposit of every deploy and write. Studio cannot import a CLI keystore, so fund its address with `sim_fundAccount`, the same RPC method the 💧 button calls. Pass the address from `genlayer account` and an amount in wei (here 100 GEN), and send the request to the RPC of the environment you selected:

```bash
# Studionet: https://studio.genlayer.com/api
# Studio-dev: https://studio-dev.genlayer.com/api
# Localnet:   http://localhost:4000/api
curl -s https://studio.genlayer.com/api \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"sim_fundAccount","params":["<your-cli-address>",100000000000000000000]}'

genlayer account          # the balance now includes the funded GEN
```

Alternatively, send GEN from another funded CLI account with `genlayer account send <address> 100gen`. Balances are per chain: GEN on Studionet does not exist on Studio-dev or Localnet.

### Step 3: Write your contract

Intelligent Contracts are Python files that can use GenVM capabilities such as LLM calls and web access. Start with [Your First Intelligent Contract](/developers/intelligent-contracts/first-intelligent-contract), either in the Studio editor or in a local `contracts/` folder.

### Step 4: Deploy

**From the Studio UI**

1. Upload the file with **Add From File** and open it in the editor ([Loading a Contract](/developers/intelligent-contracts/tools/genlayer-studio/loading-contract)).
2. Open **Run and Debug**, check the detected **Constructor Inputs**, and click **Deploy** ([Deploy Contracts](/developers/intelligent-contracts/tools/genlayer-studio/deploying-contract)).
3. When the deployment finalizes, the contract address and its methods appear in the same panel.

**From the CLI**

Fee-charging Studio environments reject deploys that carry no fee distribution. Pass the `fee-profile.json` generated by your tests (`gltest --fee-profile`); the CLI uses its `deploy` entry together with current network prices:

```bash
genlayer network set studionet   # or: localnet / studio-dev
genlayer deploy \
  --contract contracts/my_contract.py \
  --fee-profile fee-profile.json
```

The contract from Step 3 has no constructor parameters, so the command passes no `--args`. For contracts whose `__init__` takes parameters, add `--args` with values in the same order and types, for example `--args "Hello" 42`.

The CLI prints the transaction hash and the contract address. See [Fee Profiling and Estimation](/developers/decentralized-applications/fee-profiling-and-estimation) to generate the profile and choose a `--fee-preset`, and [CLI Deployment](/developers/intelligent-contracts/deploying/cli-deployment) for argument types.

**From a deploy script or GenLayerJS**

Create the client with the chain object that matches the environment (`localnet`, `studionet`, or `studioDevnet` from `genlayer-js/chains`), estimate fees from your fee profile, deploy, and wait for finalization. [Deploy Scripts](/developers/intelligent-contracts/deploying/deploy-scripts) has a complete example; use it for multi-contract deployments or constructor arguments the CLI cannot express.

### Step 5: Verify and interact

1. Confirm that the deployment finalized and that its execution result is successful. A returned transaction hash on its own does not mean the deployment succeeded.
2. Look up the transaction or contract address in the environment's explorer ([Networks](/developers/networks)).
3. Call the contract from Studio, from the CLI (`genlayer call` / `genlayer write`), or from your frontend, using the same environment you deployed to.
4. Hosted Studio environments can be reset. Keep contract sources and deploy scripts in your repository so you can redeploy, and do not depend on Studio-dev state.

## 2. Moving to Advanced Workflow

As projects transforms to real-world applications, developers should migrate to a local development setup. This approach mirrors frameworks like Hardhat or Foundry and is well-suited for iterative development and comprehensive testing.

### Benefits of Local Development:
- **Complete Control**: Developers can configure the environment, validators, and network parameters as needed.
- **Enhanced Debugging**: The local setup allows for advanced debugging of both contracts and transactions.
- **Flexible Testing**: Tests can simulate real-world scenarios, including edge cases and complex interactions.

### Workflow Steps:
1. **Set Up Your Local Environment**: Developers can start with the GenLayer boilerplate project, which includes pre-configured templates for local testing.
2. **Write Tests**: Tests are written in Python, focusing on validating contract functionality and ensuring consensus integrity. The boilerplate includes sample tests to accelerate development.
3. **Profile Transaction Paths**: Cover normal, expensive, message-emitting, and failure branches in tests, then generate a `fee-profile.json` for application submissions.

## 3. Building the Frontend with GenLayerJS

The frontend is the user-facing component of a DApp. With **GenLayerJS**, developers can integrate their applications with the GenLayer network, focusing on providing a seamless user experience.

### Why Use GenLayerJS?
- **Simplified Interactions**: Abstracts the complexity of blockchain interactions with high-level APIs.
- **Comprehensive Features**: Supports transaction handling, contract interaction, event subscriptions, and account management.
- **TypeScript Integration**: Provides type safety and code reliability for frontend development.

### Frontend Development Workflow:
1. **Integrate GenLayerJS**:

Install the SDK and set up a client to connect to the GenLayer network. Configuration options allow connection to various environments, such as testnets or the GenLayer Studio.
Refer to [GenLayerJS](/developers/decentralized-applications/genlayer-js) guide for more information.

2. **Read and Write to Contracts**:

Use the SDK's high-level APIs to interact with deployed contracts. For instance, retrieve user balances or update contract state seamlessly.
Refer to [Reading Data](/developers/decentralized-applications/reading-data) and [Writing Data](/developers/decentralized-applications/writing-data) guides for more information.

3. **Estimate and Review Fees**:

Use the measured profile plus current network prices to show a quote before signing. [Transaction Kit](/developers/decentralized-applications/transaction-kit-integration) supplies the fee-review and wallet flow for React, Vue, or a headless frontend.

4. **Monitor Transactions**:

Track the returned transaction ID to a decision or finalization. Treat the operation as successful only when its status and execution result both indicate success.

5. **Build the User Interface**:

Combine GenLayerJS with popular frontend frameworks (like React or Angular) to create intuitive interfaces.

## Advanced Tips for Developers

1. **Leverage GenVM Features**:

The GenVM allows Intelligent Contracts to interact with LLM models and access real-time web data. Developers should design contracts to maximize these capabilities for dynamic and intelligent DApps.

2. **Optimize Testing**:

Incorporate edge case scenarios in tests to ensure that contracts behave reliably under all conditions.

3. **Focus on Security**:

Implement robust security measures, including input validation and error handling, to protect contracts from malicious inputs and ensure consensus consistency.
