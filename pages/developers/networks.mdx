# Networks

GenLayer operates as two layers: the **GenLayer RPC** handles intelligent contract operations (`gen_*` methods), while the **GenLayer Chain** is the underlying Arbitrum Orbit L2—settling to Ethereum, with GEN as its native gas token—that handles standard Ethereum operations (`eth_*` methods). The GenLayer RPC also passes through supported `eth_*` calls to the underlying chain, so you can use either endpoint for standard wallet operations. See [GenLayer Chain integration](/understand-genlayer-protocol/core-concepts/rollup-integration) for how the chain, bridge, and settlement work.

For the full RPC reference, see [GenLayer Node API](/api-references/genlayer-node).

For transfers and staking, connect to the **GenLayer Chain RPC**. Intelligent-contract methods such as `gen_call` require a **GenLayer node RPC**; the Conduit chain RPC does not provide them. Use a Phase 3-compatible GenLayer node endpoint for SDK intelligent-contract operations.

## Testnet Clarke

Public testnet for testing your contracts before production, running GenVM v0.4. It is a separate deployment of the Bradbury Phase 3 contracts on the same GenLayer Chain, so it shares Bradbury's chain ID, RPC, explorer, and GEN balances.

| Setting | Value |
|:--|:--|
| **GenLayer RPC** | Not published yet |
| **GenLayer Chain RPC** | `https://rpc.testnet-chain.genlayer.com` |
| **Chain ID** | 4221 |
| **Currency** | GEN |
| **Chain Explorer** | [scan.testnet-chain.genlayer.com](https://scan.testnet-chain.genlayer.com/) |
| **Faucet** | [testnet-faucet.genlayer.foundation](https://testnet-faucet.genlayer.foundation) |
| **Bridge** | [testnet.bridge.genlayer.com](https://testnet.bridge.genlayer.com) (see [Testnet Bridge](/developers/testnet-bridge)) |
| **AddressManager** | `0xA79dA7c238905fD0F10298cD579B0733ad1B1d0E` |

<Callout type="warning">
Chain ID **4221** does not tell Clarke from Bradbury: both deployments live on the same chain. Select the deployment explicitly with the `testnetClarke` (genlayer-js) or `testnet_clarke` (genlayer-py, genlayer-test) preset, and verify that the AddressManager is the one above.
</Callout>

Transactions and staking go through the GenLayer Chain RPC. Reads such as `gen_call` need a Clarke GenLayer node RPC, which is not published yet.

## GenLayer Chain (L2)

The underlying Arbitrum Orbit L2 for Clarke and Bradbury Phase 3. GEN is its native currency, so balances and gas are in GEN. You typically don't need to interact with this directly — the GenLayer RPC passes through supported `eth_*` calls. But if you need direct L2 access (e.g., token transfers, contract debugging at the EVM level), you can add this chain to your wallet.

## Recommended Flow

1. **Start on Studionet** — zero setup, open [studio.genlayer.com](https://studio.genlayer.com)
2. **Use Studio dev only for release-candidate validation** — open [studio-dev.genlayer.com](https://studio-dev.genlayer.com) with the matching RC tooling
3. **Move to Localnet** — when you need full control and fast iteration
4. **Deploy to Clarke** — when ready for production-like testing with real AI workloads
5. **Use Bradbury** — to try new protocol features before they reach Clarke
